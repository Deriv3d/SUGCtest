# Phase 1: Data first

Goal: understand every file on the disc well enough to load it from our own Rust code, and
know exactly how the bundled ROMs are stored and handed to the emulator.

## Split of work

- **On the owner's PC (lab)**: format analysis, Ghidra work on the loaders, round-trip runs
  against the real files. Findings come back as format notes in our own words.
- **In the repo**: `crates/sugc-formats` (parsers + writers), `crates/sugc-lab` (CLI that
  runs round-trips and extraction against a user's own disc), `crates/sugc-viewer` (asset
  viewer). Tests use synthetic files generated by the tests themselves.
- Every commit passes `publish-check --game-dir` against the lab extraction before push.

## Steps

1. **Classify all 27 files** by magic, size and the code that opens them (Ghidra xrefs to
   `sys_fs` / `cellFs` open calls). Each file gets a format name and an owner step below.
2. **ROM archive** (the zlib-packed archive with 147 entries): table layout, compression,
   per-entry metadata, and what the 105 non-ROM entries are. Then follow the code path from
   archive read to the emulator core: where the ROM buffer is decompressed, whether any
   header or patch is applied, and the function that receives it.
3. **Other containers and assets**: UI textures, fonts, museum/unlockable content, audio.
   Decode each to a standard in-memory form (RGBA image, glyph atlas, PCM).
4. **Viewer**: browse the archive, view textures and fonts, play audio.

## Definition of done

- Every file on the disc is classified, and each container format has a format note in
  `knowledge/formats/`.
- Each container parser round-trips (parse, re-serialize, byte-compare) on the owner's copy,
  run by `sugc-lab roundtrip`. Results are recorded as pass/fail counts.
- ROM handling is documented: storage, compression, any per-game header or patch, and the
  hand-off function to the emulator.
- The viewer shows textures and fonts that the owner confirms match what the game shows.

## Verification against RPCS3

- **ROMs**: boot one game in RPCS3, dump guest memory over the GDB server, and confirm the
  ROM image our parser extracts is byte-identical to the one in guest memory (or document
  exactly what differs and why). Also check each ROM's internal header checksum.
- **Textures**: compare a decoded UI texture against the same texture resource in a
  RenderDoc capture of the menu that uses it.
- **Audio**: compare a decoded sound against the loopback recording of the same sound.
